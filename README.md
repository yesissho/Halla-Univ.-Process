# 제주한라대학교 AID사업단 업무 진행 관리 도구

사번과 개인 비밀번호로 가입·로그인하며, 업무·계획·시행·지급 문서와 공문은 로그인한 사번의 서버 저장소에만 조회·저장됩니다. 같은 계정으로 다른 PC에서도 이어서 이용합니다.

## 사용

- 첫 접속: **사번 등록** → 숫자 사번(3~20자리), 비밀번호(8~128자), 비밀번호 확인.
- 이후 접속: **로그인**. 상단에 현재 사번과 로그아웃 버튼 표시.
- 새 계정은 빈 문서함으로 시작합니다. **백업·복원 → 이 PC의 기존 자료 가져오기**에서 로그인 도입 전 이 브라우저에 저장된 본인 자료를 확인하여 가져올 수 있습니다. 다른 PC 자료는 JSON 백업·복원으로 이동합니다.
- 입력한 사번의 실제 재직 여부를 확인하는 절차는 없으며, 먼저 등록된 사번을 계정 식별자로 사용합니다. 기존에 등록된 사번으로 다른 계정을 만들 수 없습니다.
- 비밀번호는 개별 salt와 PBKDF2-SHA256 해시로 저장하며 원문은 저장하지 않습니다. 현재 비밀번호 분실 복구·재설정 기능은 제공하지 않습니다.
- 세션은 Secure/HttpOnly/SameSite=Strict 쿠키이며 8시간 후 만료됩니다. 모든 문서 API에서 서버가 세션의 사번을 기준으로 권한을 확인합니다. 클라이언트가 전달한 다른 사번을 소유자로 사용하지 않습니다.
- 여러 창에서 동시에 저장하면 먼저 반영된 수정 사항을 보호하고, 뒤늦은 저장에는 충돌 안내를 표시합니다. 입력 내용은 유지되므로 백업 후 새로고침합니다.
- 로컬 폴더 생성은 PC Chrome/Edge에서 지원하며 폴더 연결 정보는 브라우저·계정별로 보관합니다. 로컬 폴더와 파일이 서버에 업로드되지는 않습니다.
- 자료 저장 실패 시 완료로 표시하지 않고 현재 창에 이유를 표시합니다. 한 계정의 저장 요청 크기 한도는 약 1.5MB입니다.

## 소스와 실행

- `src/`: 기존 대시보드와 사번 로그인 화면.
- `worker/index.js`: 인증·계정 등록·사번별 데이터 API. Cloudflare Worker / Sites D1의 `DB` 바인딩 사용.
- `db/schema.ts`, `drizzle/`: 스키마와 누적 마이그레이션. 이전에 적용된 마이그레이션은 변경하지 않습니다. 과거 관리자 발급 계정 테이블은 보존하며 현재 사번 등록은 별도 테이블을 사용합니다.
- `scripts/build.mjs`: 자산을 내장한 `dist/server/index.js` 생성. 공개 배포 파일에 비밀번호, 세션, 사용자 문서는 포함하지 않습니다.

```sh
npm ci
npm run check
npm run build
npm test
```

로컬 UI 미리보기는 `npm run dev -- --host 127.0.0.1 --port 4173`. 테스트용 SQLite는 `.sites-runtime/preview.sqlite`에만 생성됩니다. 실제 배포는 Sites가 D1과 마이그레이션을 연결합니다. 현재 서버 구현은 Sites/Cloudflare Worker용이며 Vercel의 정적 호스팅만으로는 인증·서버 저장 기능을 실행할 수 없습니다.
